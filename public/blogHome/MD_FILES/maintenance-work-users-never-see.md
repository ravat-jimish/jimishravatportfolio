# The maintenance work users never see

Refactoring, observability, and documentation are quiet investments. Users may never notice them directly, but they feel the effect in a product that stays reliable.

## Make change affordable

Small modules, useful logs, and focused tests turn future work from a risky event into a normal part of the product's life.

Maintenance is not work that happens after the real work. It is how the real work keeps delivering value over time.
