# What I learned from working across the stack

Working across interfaces, APIs, and infrastructure changes the way you think about ownership. Each layer makes the constraints of the others more visible.

## Follow the data

When a feature feels confusing, trace the data from the user action to the final result. This often reveals a contract that was assumed but never written down.

## Communication is part of the implementation

A small diagram, a clear pull request description, or a useful test name can remove more uncertainty than another hour of coding.

The stack is not a set of isolated specialties. It is one connected experience for the person using the product.
